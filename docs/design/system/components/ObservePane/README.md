The Observe pane set is stage 4, built today, and the proof that the grammar holds for a built stage: the availability banner, the two connectors, the alerts and the live trace, composed as a main stream and a side stack.

- The consumer provides the listener's window for the agent (events and marks, each replayed or live), the two connectors' status and last heard, the alerts with their kind, subject, summary, detail, occurrences and version, and whether the person may acknowledge.
- The live trace is a `.stream` in `id`: sequence, time, then the event's fields as they came. The time is the event's `wall_ms` as the trace envelope carries it, a number of milliseconds, never a clock reading the browser computed. A replayed row is `dim` with `replayed` in `hold`: each event in the window carries `replayed`, the listener's verdict against the opening's boundary. A discontinuity is a hatched `.mark` row at the gap with its reason. An absent member in a row is an `absent` pill, never a blank. The raw event stands in `pre.raw` beneath.
- On the served agent page the stream is rendered in the browser by the trace module (`assets/surfaces/trace.js`), a file of the binary under the script policy: it opens the stream the list names in `data-stream` and places the event's own words, its column for the time 8em (a served rule of `bundle.css`, since a monospace digit is 0.6em and the stamp thirteen digits), the window's word in the footer, and the view's closing reason there when the session or the grant ends. The pane bounds the list (`.pane .stream`, 60vh, scrolling within the pane, a served rule) and the module keeps a reader at its end at the newest row, leaving a reader scrolled back where they are; it drops no row, so the list holds what the window sends. It computes nothing the stream did not send.
- The header's source line names the relay, the door's state and the boundary; the footer says the stream is the listener's window and not a record, and that the session and grant are re-checked every 15 s.
- Connectors show each plane's word from the listener: `connected` or `not connected`, last heard, and admin-con's ceiling. Presence is derived from both planes and said in words.
- An alert row carries its kind in `id`, its state as a status mark, its reason verbatim and its count. Acknowledge is a form with the version read; a decision standing links to the decision pane rather than resolving here.
