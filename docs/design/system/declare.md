# Declare: the setup pages

Declare is a start page, the setup pages and the build page, on the operator's rulings of 2026-11-16 (setup pages) and their addendum, which replace the two screens of the rulings of 2026-11-11 as the stage's path, and on the operator's rulings of 2026-11-23. The agent is named where its box is paired, on Pair a box, Provision's page ("Pairing is its own page", and "the agent is named at pairing"), and the start page, Declarations, lists the paired agents whose declaration is open. The declaration starts at directories ("The declaration starts at directories, not drives"): the setup pages run the directories, the models, the placement and the confirmed deployment tuple, in that order. The build page holds the board, where the operator wires what was declared and sees only that, and the prompt tuple panel, both held. Spec section 6.2 carries the pages, and section 6.1 the declaration screen. An agent is binaries by hash plus wires by hash, and the setup pages and the board are a rendering of that card. The trace is the record and not a component, so no page declares it.

## The setup pages

The pages are built to the confirm page, each part live or held (Spec 6.2). A held pane names what it waits on, the enrollment, the box's report or WeaverAgent's terms, and shows no value it did not read, so the pages alone reach no confirmed deployment tuple until the box reports. A load refuses a confirmed agent until the prompt tuple carries the six sampling values. Every page is panes under the pane grammar, each pane carrying its stage, its backing and its status, healthy states included.

- **Before the start page**, the console connects the operator's Hugging Face account once, as a console setting. The setting accepts a read-only or a read-write token, held sealed, and the console never writes to Hugging Face except on an explicit push in Train (Spec 2.15). The operator's SSH public keys are a console setting too, one or more, each shown by its fingerprint (Spec 6.2).
- **Pair a box comes first, under Provision.** It asks the agent's name, one field, and lists the named agents whose box is not yet paired. An agent's pairing says what to do at the appliance: log in at its console, where the setup prompt at the first console login starts the appliance's setup script; the script walks the operator through finishing setup, the disks included, and ends in pairing, asking this server's address and port, which the page shows. The page shows the box waiting, which dialed this server from the script. The operator compares the fingerprint the box shows with this server's own, in four rows of four groups as the script shows it (a lean, the operator's to rule), and enters the short one-time code the box shows. A checkbox says whether the box is a virtual machine or a host, and the page warns where the console's link address is a loopback address and the checkbox says virtual machine, and where it is an unspecified address. Once the box is paired, the page's way on is the declaration's first page, the directories (a lean, the operator's to rule) (Spec 8.2).
- **The start page, Declarations,** lists the paired agents whose declaration is open.
- **The models.** The models directory's need, the bytes of the picks' distinct blobs, judged against the models directory the box reports and the 10 GiB margin, a warning only. A Hugging Face repository, then a pick from its files, a split model shown as one choice with all its parts, and the precision read from the file. Hugging Face is the one source, and a local source is later. What the first agent does not need, extra models, adapter roles beyond the one decoder adapter, a classifier-only agent and placement on the CPU, is drawn and marked unbuilt, never live, so a page never accepts what a load refuses.
- **The directories.** The declaration starts here. On an appliance the operator lays the disks before pairing, with the appliance's setup script, a state disk and a models disk at least 10 GiB larger than the model, each mounted at its default path, and this server lists and formats no disk. The page shows the two directories as the box's latest report of either stage shows them: the state directory, under which each agent has a directory of its own, named for it, holding the agent's folder and its home side by side, and the models directory, at the state mount and the models mount. Beside them stands the box's survey at the pairing stage, its members grouped, or the cause it was refused (a lean, the operator's to rule, where this report shows). The agent's accounts are laid at setup and take its name, and the image carries no fixed account for the agent (Spec 6.2). The trace is never written to the agent's state or anywhere the agent can reach, on the operator's word of 2026-11-17: it goes to this server, which stores it outside the agent's reach, so no folder on the state drive holds it beside the agent's state or save points. The SSH keys that go down and the directories as mounted are live, the directories from the latest report of either stage: a directory not mounted, or a state directory whose filesystem is under 9 GiB, holds Confirm, and a models directory with less free space than the need, or with a filesystem under the need and the 10 GiB margin (a lean, the operator's to rule), is warned of (Spec 6.2). On a host, which attaches and formats nothing, the page draws one row, marked unbuilt since the host's own script is later: the models directory, from this server's `model_cache`, or `not set`. The host form, planned and not drawn, asks the state directory and the models directory the operator names, the state directory writable with at least 10 GiB free and the models directory readable, with no separate disk asked, on the operator's addendum. Its models directory is prefilled with that user's default Hugging Face cache, so models already pulled there are found, and beside it the form shows a command for the operator granting this server's account read-write on that cache and a models group read. This server alone talks to Hugging Face and writes there, and agents on the machine read the model in place, read-only, through the group, since several may share one model.
- **The placement.** Each model on a device, and the context length chosen from the box's max-tokens-per-turn to the model's maximum, read from the file's header, with the turn context. The context length, the turn context and the devices are live, the devices once the box reports its cards, and a kept card a later report lacks is named, and the fit is held until the room plan. The fit is called planned, from the room plan without a load, since only a load measures. "In shard order" names the layer split across cards and says so.
- **Confirm.** The deployment tuple in full: the model's repository, commit and per-part digests, the adapter likewise, the appliance's version (the survey's image members; a lean, the operator's to rule), the driver, the cards by model, each with its ordinal in PCI bus order, the guest CPU, the machine, the drives, the placement and the context length, the box's members from its latest report of either stage. Confirm stands only once every member is read, and goes to the build page.
- **The build page** is a one-pane stub marked unbuilt until the board and the prompt tuple panel come.

One unit, GiB, serves every size in the flow.

## The declaration screen, as built

The declaration screen of the rulings of 2026-11-11 is built and stays beside the setup pages, reached from the build page's stub for the fields no setup page asks (Spec 6.1 and 6.2). The screen is a form of panes, under the pane grammar every surface uses, and never a canvas. Nothing on it is dragged or placed.

- **The agent pane** holds the name, which names the lineage and never changes within it.
- **One pane per SPU box.** A box stands for the models it holds: four models declared apart are four boxes, one decoder with its adapter is one box, and the operator chooses which. Each model row carries its function from the roster the framework charters (the decoder, exactly one; the classifier, optional), its artifact, its format and, on a decoder, its adapter. GGUF is the one format offered; the others are named as later and not offered. The box's GPU requirement sits in the box's pane: a card, a class (a family the capability table knows, or a list of models; the form typed is kept), or a pair in shard order. Start satisfies the requirement or refuses; it never substitutes.
- **The sampler pane** holds the tunable values a serving load requires at the pinned corpus commit, eight since 2026-11-12, every one required (Spec 6.1). Six are the sampler's defaults, which every generation carries and the record states: temperature, top-k, top-p, the repetition penalty, the repetition window and the seed. Two are the session's, fixed at load: the maximum tokens per turn, the ceiling each generation's own bound sits under, and the context capacity. A new form starts with five filled, the constants the agent ran with before the declaration carried them (temperature 0.7, top-k 40, top-p 0.95, repetition penalty 1.1, repetition window 64), each editable; the seed and the two session values start empty. Each field is refused at save outside the agent's range, naming it. What else is fixed at load, the sampler's mechanism among it, is shown read-only beside the model once an agent reports it, and until then the pane says what that waits on.
- **The store and gate pane** holds the store (`none` or `sqlite`) and the gate's tool election (no tool, or `sh`). Who the gate admits is its gate-con, filled at Provision, and is not asked here.
- **The prompt pane** holds the system prompt as its own field, never attached to a model. The declaration act writes it into declared state; from then on it is read from state and never from a file, and a change is a reload.

Two panes read the saved document back, beside the form:

- **The agent's file**: `agent.toml` in the agent's grammar at the pinned corpus commit, derived and never edited. What the screen does not declare is a comment naming what fills it, and what the grammar has no place for is a trailing block naming its interface question.
- **The prompt as it will be written**, with its waits-on line, or the word that there is none.

## The rules

- **A saved declaration is a versioned document.** Every save is a new row in its lineage, with a version and a last-save time; reopening a row reopens the same document. A save from a row that is not its lineage's head is refused.
- **The form refuses on its own, naming the field**, only what it can judge alone: a missing required field, a requirement that names nothing, and a field out of its shape (Spec 6.1 lists each). A refusal is in `fail`, at the field.
- **It warns, and saves all the same,** where a class spans more than one compute capability; it never refuses for it. The warning is in `hold`, at the requirement. A card model or a family the repository's table does not know is named "capability unknown" and never left blank.
- **Each field carries what it waits on before it takes effect**, as a line under the field in `dim`: Provision's register, the declaration reaching the agent, `validate`. Spec 6.1 holds the table. Beside its label it carries when a mistake there is caught, `.when.now` or `.when.load` (the brand book's controls). A clean `validate` is acceptance for filing, not approval to load.
- **The screen reaches no agent and no host.** It writes the store and nothing else.
- **The path at the bottom of the pane** says where you are and what is left: the components, saved as a document; then the board, unbuilt; then Provision, which `validate` closes before Run opens.

## The board, when it comes

Components are compiled primitives the harness is pre-wired to. A wire is one ask and one return, written in Python by the operator. A function that makes several asks is a node the wires converge on. A wire edit is a new link in the lineage, not a reload of the same agent. None of this is drawn or built yet, and no page carries a wire or Python until the board's own act. The agent's edge, its two sockets and the two connectors outside it are drawn on the board when it is designed, not on the declaration screen.
