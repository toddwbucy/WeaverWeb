# Brief: the pane grammar on the served pages

From the planner seat to the executor, 2026-11-07. The design system of 2026-11-06 (`docs/design/system/`) is the record of how every surface is composed: tokens, a masthead, a stage rail across the eight stages (PRD 3.0, #54), panes in a grid, marks that are words in pills, controls that are real forms. The served pages still wear the seed's look (`assets/surfaces/instrument.css`, 116 lines; `main.listing`, `.listing-head`, `.chip-row`, `table.record`) and the design system's stylesheet (`components/bundle.css`) is served nowhere. This act makes the served pages the grammar's, agent page first. It is the first act under the stacked process (`CLAUDE.md`, "How we work", #60): one stack branch, three sub-PRs, the operator merging each into the stack. Land this brief as `docs/project/brief-2026-11-07-the-pane-grammar.md`, the stack's first commit.

## Sub-PR 1: the stylesheet and the frame on every page

**The served stylesheet is the design system's, derived and pinned.** `assets/surfaces/instrument.css` becomes exactly `docs/design/system/tokens.css` followed by `docs/design/system/components/bundle.css` with its `@import` line removed, and nothing else. A unit test in `src/surfaces/mod.rs` (beside `stylesheet`) reads the three files with `include_str!` and asserts the served file equals that concatenation byte for byte; its failure message names the command that regenerates it (a `sed`/`cat` line, put in a comment at the top of `bundle.css` too). Reasoning: one grammar, one copy that is the record (the design system's, whose previews import the same files), and a served copy that cannot drift. Everything the surfaces need lives in `bundle.css`; where a served page needs a rule the grammar lacks (Record's empty state and its "more" link, the sign-in and enroll forms' width, the handover and token pages' one-time notice), add it to `bundle.css` under a `/* ---- served surfaces ---- */` section with the rule's reason, and name it in the component README it belongs to (Marks, Controls or Pane). The seed's names (`--sans`, `--mono`, `main.listing`, `.listing-head`, `.destination`, `.chip-row`, `.chip-note`, `.wrap`, `table.record`, `.empty`, `.more`, `.planes`) leave: the templates move to the grammar's names, and no rule is kept for a class no template uses.

**The masthead** (`src/surfaces/templates/instrument.html`, the base) is the Masthead README's: brand, the server pages the person reaches, the open-alert count as a `.status.fail` pill when above zero, who and their highest role in `.who`, sign out. The agent switcher (`.agent-switch`) is drawn in the README for later multi-agent management: do not add it; the masthead carries no agent. The availability banners keep `.unavailable` and their words. The base template takes a `rail` block, empty by default, rendered between the masthead and `main`; sub-PR 2 fills it on the agent page.

**The pane frame on every page.** `main` becomes `.workspace`. Each page's heading becomes a title and lede in the Workspace README's shape (the title in `title`, the lede in `dim`), and each list or form the page holds becomes a `.pane` with a header (a title; a stage mark where the page is a stage's, which on this sub-PR is Register, stage 2 Provision, and Agents, which feeds stages 2 and 8 and takes no mark; a backing badge `built` on every pane, since every served pane is; a source line saying what the pane reads, in the README's words), a body (`.flush` for a table), and a footer where the page has a standing note (the persons page's disable note, the passkeys page's removal note, the grants page's own-grant rule). Marks: `you`, `this session`, `agent retired` become `.pill`; Record's chips become `.pill.query` with the plain `.pill` reading "clear"; an absent value that the seed renders as a blank or a dash becomes `.absent` with the word the Spec's section 6 gives it. Controls: every button stays a real form; the one action on a pane gets `.primary` (at most one per pane); verb buttons are sub-PR 2's. The pages: Record, sign-in, enroll, passkeys, agents list, persons, grants, register, handover, token, verb answer, decision. The agent page gets the frame too on this sub-PR, as one pane holding what it holds today; its composition is sub-PR 2. No page gains or loses a word of its content, a form, a field or a link; the shape changes and the text does not, except where a heading becomes a pane title. Where the seed's text names the seed's look ("an event stream" beside the trace link stays, it is true), keep it.

**Tests.** The markup tests that exist are listed under "The pins" below and must keep passing. Add, in the surface module that renders the base, one test that every served page carries `class="masthead"`, `class="workspace"` and the stylesheet link, rendered through the real templates against a `fresh_store` where a page needs one (the admin pages' tests already render them; extend an assertion in each rather than adding a rig). Perturbation: drop the `workspace` class from the base, and the test fails.

## Sub-PR 3: the live trace pane

The stream `GET /agents/{ag}/trace` is JSON over SSE and stays so. The pane renders it in the browser from a hand-written module of the binary, `assets/surfaces/trace.js`, served at `/assets/surfaces/trace.js` beside the passkey module and under the same script policy (the precedent is `passkeys.js`, 91 lines; stay near that size, and stop and report if the module wants more). The module opens an `EventSource` on the stream's URL, which it reads from a `data-stream` attribute on the pane's `.stream` list (no inline script, no URL in the script), and appends one `li` per event in the ObservePane README's shape: `.seq`, the time, then the event's fields as they came, an `.absent` pill for a member the event does not carry; a `replayed: true` row gets `.replayed` and a `.status.hold` pill reading `replayed`; a mark gets `.mark` with its reason; the window's own `window` event sets the footer's word. The raw event stands in `pre.raw` beneath the list: the last event received, verbatim. The browser computes nothing the server did not send: it places words and classes, and the words are the event's. On the stream's `close` event (the view's reason: the session or grant ended) the module writes the reason into the footer and stops. The pane's header source line names the relay, the door's state and the boundary as the page knows them from the register row; the footer says the stream is the listener's window and not a record, re-checked every 15 s.

**Spec.** Section 6's asset sentence (about line 3197) names four assets once this lands: the stylesheet, htmx, the passkey module and the trace module; section 2.13's live-view sentence (about line 1822) gains that the agent page renders the stream in its Live trace pane through that module and the stream itself is unchanged. Section 9: the row that pins the script policy gains the module (a perturbation that puts an inline handler in the trace pane is refused by the policy; show it in the browser as the policy's own measurement was shown on 2026-10-08, and say what was measured in the PR body). The ObservePane and Marks READMEs' sentences "the row's rendering is the pane grammar act's" become the current state: the row is `dim` with `replayed` in `hold`.

**Tests.** The module is not unit-tested in Rust; the route is: a test that `GET /assets/surfaces/trace.js` answers `text/javascript` under the script policy header, and that the agent page carries the `.stream` list with its `data-stream` naming the agent's trace URL (perturbation: drop the attribute, and it fails). Load the page in a browser against the scratch server with a fake admin-con from `admin_con_tests`' rig or a replayed file if one is at hand, and put one screenshot's description in the PR body: a replayed row dim with its pill, a live row plain. If no rig reaches a browser in an hour, say so and skip the screenshot; the route test stands.
